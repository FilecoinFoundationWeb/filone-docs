# rclone

rclone connects to Fil One as an S3 remote with `provider = Other`, SigV4 signing, path-style addressing, and a key scoped to the bucket's region.

| Setting | Value |
| --- | --- |
| Endpoint | `https://s3.eu-west-1.filonecontent.com` or `https://s3.us-east-1.filonecontent.com`, matching the bucket's region |
| Region | `eu-west-1` or `us-east-1` |
| Addressing | Path style (`force_path_style = true`) |
| Authentication | SigV4 access key and secret scoped to the bucket's region |
| Provider | `Other` |
| Upload cutoff | `0` (`upload_cutoff = 0`) |

Validation status: Verified. Tested with rclone 1.76.0 in `eu-west-1` and `us-east-1` on 2026-11-25, using the settings on this page.

## Configure

Run `rclone config`, create a new remote, choose **Amazon S3 Compliant Storage Providers**, and select **Other** as the provider. Enter the bucket's region and endpoint when prompted, enable path-style access, and enter credentials at rclone's prompts. In the advanced options, set `upload_cutoff` to `0`, or add the line to `rclone.conf` afterwards. The resulting section in `rclone.conf` looks like this:

```ini
[filone]
type = s3
provider = Other
access_key_id = ACCESS_KEY
secret_access_key = SECRET_KEY
region = eu-west-1
endpoint = https://s3.eu-west-1.filonecontent.com
force_path_style = true
upload_cutoff = 0
```

With `upload_cutoff = 0`, rclone verifies every upload against an MD5 checksum it stores with the object, rather than comparing it with the object's ETag. Use it in both regions. It's required in `eu-west-1`, where ETags aren't MD5 checksums.

Test discovery without changing remote data:

```bash
rclone lsd filone:
```

## Examples

1. Copy with `rclone copy ./fixture filone:BUCKET/example/` and list with `rclone lsjson filone:BUCKET/example/`.
2. Restore with `rclone copy filone:BUCKET/example/ ./restored`.
3. Run `rclone check --download ./restored filone:BUCKET/example/`.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| `corrupted on transfer: md5 hashes differ` | Set `upload_cutoff = 0`. |
| Signature mismatch | Endpoint, region, and key must refer to the same region; confirm `force_path_style = true`. |
| Bucket not found | Confirm the bucket already exists and the key is scoped to it. |
| TLS error | Keep certificate validation enabled; inspect local proxy or trust-store configuration. |
| Cleanup leaves data | List the exact prefix and remove only that prefix. |
