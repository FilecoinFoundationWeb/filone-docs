<details>
<summary>Is Fil One S3-compatible?</summary>
<div>

Yes. Fil One provides an S3-compatible API, and the standard S3 SDKs and tools work with it once you make two changes: set the endpoint to your region's (`https://s3.eu-west-1.filonecontent.com` or `https://s3.us-east-1.filonecontent.com`), and turn on path-style addressing. Some S3 features are not available, such as bucket policies and lifecycle rules. Check the [S3 Compatibility Reference](/reference/s3-compatibility) for the operations your application uses.

</div>
</details>

<details>
<summary>Do I need to know anything about blockchain or cryptocurrency?</summary>
<div>

No. Fil One is a standard cloud storage service. You sign up with an email, store data using familiar S3 tools, and pay with a credit card. The underlying storage infrastructure handles everything else transparently.

</div>
</details>

<details>
<summary>Where is my data stored?</summary>
<div>

You choose the region when you create a bucket. Fil One currently offers **Europe (France)** as `eu-west-1` and **US East (Michigan)** as `us-east-1`. Objects in a bucket stay in that bucket's region, and the region cannot be changed afterwards, so pick it deliberately if data residency matters to you.

Within a region, storage is fulfilled by a distributed network of storage providers on Filecoin. All data is encrypted at rest. See [Limits & Quotas](/limits) for the region list and [Encryption](/security/encryption) for how encryption is handled.

</div>
</details>

<details>
<summary>What happens when I delete an object or bucket?</summary>
<div>

On a bucket **without versioning**, the object disappears from your account immediately and there is no recycle bin or undo.

On a bucket **with versioning enabled**, a delete over the S3 API without a version ID places a delete marker instead. The object stops appearing in listings, but every prior version is kept and can still be downloaded by version ID, and you can make the object visible again by deleting the delete marker. Those retained versions continue to count as stored storage. Deleting from the dashboard is different: it always removes the specific version you chose, permanently, and never writes a delete marker. See [Versioning](/storage/versioning).

Once deleted, an object or bucket is no longer accessible through the API or the dashboard. Encrypted residual data can remain in Filecoin storage for a bounded period: see [What happens to deleted data](/storage/objects#what-happens-to-deleted-data).

</div>
</details>

<details>
<summary>Can I migrate from AWS S3?</summary>
<div>

Yes. Because Fil One is S3-compatible, you can use standard migration tools like `aws s3 sync`, `rclone`, or any S3-compatible transfer utility. Point the tool at your Fil One endpoint and credentials (with path-style addressing enabled — see [SDKs & Tools](/sdk/overview)). One naming caveat: Fil One does not allow dots in bucket names, so a bucket like `my.data.bucket` must be renamed during migration.

</div>
</details>

<details>
<summary>Do you charge for egress?</summary>
<div>

On a paid plan, no. There are no egress or data transfer fees.

The free trial is the exception: it includes 2 TB of egress rather than unlimited. See [Trial & Billing](/billing/trial).

</div>
</details>

<details>
<summary>What is included in the free trial?</summary>
<div>

The 30-day trial includes 1 TB of storage, 2 TB of egress bandwidth, and unlimited API operations. No credit card is required. See [Trial and Billing](/billing/trial) for details.

</div>
</details>

<details>
<summary>Can I use Fil One for backups?</summary>
<div>

Most S3 backup tools work. Before you commit to one, check that it can:

- use **path-style addressing** (bucket names can't contain dots, either),
- sign requests with **SigV4**,
- point at a custom endpoint: your bucket's region, `https://s3.eu-west-1.filonecontent.com` or `https://s3.us-east-1.filonecontent.com`.

We haven't tested specific backup products. Three documented gaps are ones some backup tools depend on:

- **Server-side copy of a specific version is unverified in `eu-west-1`.** `CopyObject` is confirmed in `us-east-1`, and plain server-side copy works in `eu-west-1`, but copying a specific `VersionId` has not been verified there. Some tools use `CopyObject` for renames, moves, and deduplication.
- **No `CreateBucket` over the API in `eu-west-1`.** A tool that provisions its own repository bucket needs the bucket created in the dashboard first.
- **No lifecycle rules.** Retention-based pruning has to be handled by the tool itself.

See the [S3 Compatibility Reference](/reference/s3-compatibility) for the full list.

</div>
</details>

<details>
<summary>What durability guarantees do you offer?</summary>
<div>

The [Fil One SLA](https://www.filone.com/sla) commits to 99.9% monthly uptime, with service credits if it is missed.

Fil One stores data on Filecoin, where storage providers must keep proving they still hold the data they committed to store (see the data integrity question below). We don't publish a durability percentage. For details, email [support@filone.com](mailto:support@filone.com).

</div>
</details>

<details>
<summary>Can multiple users access the same account?</summary>
<div>

Yes, through organizations. An organization can have several members, each with a role: **Owner**, **Admin**, **Member**, or **Read only**. See [Organization](/app/organization) and [Roles and permissions](/app/organization#roles-and-permissions).

Access through the S3 API is still per access key. There are no IAM users or bucket policies, so to share limited access with other services, create API keys scoped to specific buckets and permissions.

</div>
</details>

<details>
<summary>How does Filecoin protect the integrity of stored data?</summary>
<div>

To check an individual object, compare the `ETag` returned by `HeadObject` with a checksum you keep. To stop an object changing for a fixed period, use [Object Lock](/storage/object-lock).

Underneath, Fil One is built on Filecoin, a distributed storage network where storage providers must continuously submit cryptographic proofs, called Proof of Replication (PoRep) and Proof of Spacetime (PoSt), to show they still hold the data they committed to store. Providers that fail to produce valid proofs are penalised. This runs at the network level, not per request.

Fil One doesn't expose per-object proof data: content identifiers, deal IDs and sealing state aren't shown in the API or the dashboard.

</div>
</details>
