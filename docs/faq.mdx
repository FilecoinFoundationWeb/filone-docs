<details>
<summary>Is Fil One S3-compatible?</summary>
<div>

Yes. Fil One provides an S3-compatible API. Any application, SDK, or tool that works with AWS S3 works with Fil One by changing the endpoint URL to your region's endpoint — `https://eu-west-1.s3.fil.one` or `https://us-east-1.s3.fil.one`. See the [S3 Compatibility Reference](/reference/s3-compatibility) for the full list of supported operations.

</div>
</details>

<details>
<summary>Do I need to know anything about blockchain or cryptocurrency?</summary>
<div>

No. Fil One is a standard cloud storage service. You sign up with an email, store data using familiar S3 tools, and pay with a credit card. The underlying storage infrastructure handles everything else transparently.

</div>
</details>

<details>
<summary>Where is my data stored?</summary>
<div>

You choose the region when you create a bucket. Fil One currently offers **Europe (France)** as `eu-west-1` and **US East (Michigan)** as `us-east-1`. Objects in a bucket stay in that bucket's region, and the region cannot be changed afterwards, so pick it deliberately if data residency matters to you.

Within a region, storage is fulfilled by a distributed network of storage providers on Filecoin. All data is encrypted at rest. See [Limits & Quotas](/limits) for the region list and [Encryption](/security/encryption) for how encryption is handled.

</div>
</details>

<details>
<summary>What happens when I delete an object?</summary>
<div>

On a bucket **without versioning**, the object disappears from your account immediately and there is no recycle bin or undo.

On a bucket **with versioning enabled**, a plain delete places a delete marker instead. The object stops appearing in listings, but every prior version is kept and can still be downloaded by version ID, and you can make the object visible again by deleting the delete marker. Those retained versions continue to count as stored storage. See [Versioning](/storage/versioning).

</div>
</details>

<details>
<summary>Can I migrate from AWS S3?</summary>
<div>

Yes. Because Fil One is S3-compatible, you can use standard migration tools like `aws s3 sync`, `rclone`, or any S3-compatible transfer utility. Point the tool at your Fil One endpoint and credentials. Detailed migration guides are coming soon.

</div>
</details>

<details>
<summary>Do you charge for egress?</summary>
<div>

On a paid plan, no. There are no egress or data transfer fees.

The free trial is the exception: it includes 2 TB of egress rather than unlimited. See [Trial & Billing](/billing/trial).

</div>
</details>

<details>
<summary>What is included in the free trial?</summary>
<div>

The 30-day trial includes 1 TB of storage, 2 TB of egress bandwidth, and unlimited API operations. No credit card is required. See [Trial and Billing](/billing/trial) for details.

</div>
</details>

<details>
<summary>Can I use Fil One for backups?</summary>
<div>

Yes. Fil One works with any backup tool that supports S3-compatible storage, including Veeam, Commvault, Restic, and Duplicati.

</div>
</details>

<details>
<summary>What durability guarantees do you offer?</summary>
<div>

Fil One is designed for high durability through distributed storage across multiple providers. Specific durability SLA details are available on request.

</div>
</details>

<details>
<summary>Can multiple users access the same account?</summary>
<div>

Currently, Fil One accounts are single-user. Each account has one login and one set of API keys. Multi-user organization accounts with role-based access are planned for a future release. In the meantime, you can create multiple API keys scoped to specific buckets and permissions to share limited access with other services or team members.

</div>
</details>

<details>
<summary>How does Filecoin protect the integrity of stored data?</summary>
<div>

Fil One is built on Filecoin, a distributed storage network where storage providers must continuously submit cryptographic proofs — called Proof of Replication (PoRep) and Proof of Spacetime (PoSt) — to prove they are still holding the data they committed to store. Providers that fail to produce valid proofs are penalised. This proof cycle runs at the network level and is not something you trigger or check yourself.

Fil One does not currently expose per-object proof data — content identifiers, deal IDs, and sealing state are not surfaced through the API or the dashboard, so you cannot independently audit an individual object today. For object-level integrity checks in your own application, compare the `ETag` returned by `HeadObject` against a checksum you keep, or apply [Object Lock](/storage/object-lock) to make objects immutable for a fixed retention period.

</div>
</details>

<details>
<summary>What happens to my data if I delete it?</summary>
<div>

When you delete an object or bucket, it is immediately removed from your Fil One account and is no longer accessible via the API or dashboard. However, the underlying Filecoin storage deals persist until their natural expiration, which can be up to 180 days. This is a property of the Filecoin network's sealed sector model. The data is inaccessible through Fil One from the moment of deletion — the Filecoin deal expiration is an infrastructure detail, not a user-facing state.

</div>
</details>
