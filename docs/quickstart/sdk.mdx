The complete upload programs for [Python](/quickstart?tool=python), [JavaScript](/quickstart?tool=javascript) and [Go](/quickstart?tool=go) are in step 5 of the Quickstart. This page explains the settings they use, so you can apply them to your own code.

## Client settings

Every S3 client that talks to Fil One needs these settings. The SDK defaults are written for AWS, and some of them fail against Fil One.

| Setting | Why | Python (boto3) | JavaScript (SDK v3) | Go (aws-sdk-go-v2) |
|---------|-----|----------------|---------------------|--------------------|
| Endpoint | Send requests to Fil One, not AWS | `endpoint_url="https://s3.eu-west-1.filonecontent.com"` | `endpoint: "https://s3.eu-west-1.filonecontent.com"` | `BaseEndpoint: aws.String("https://s3.eu-west-1.filonecontent.com")` |
| Region | Must match the endpoint and the key | `region_name="eu-west-1"` | `region: "eu-west-1"` | `Region: "eu-west-1"` |
| Path-style addressing | Fil One doesn't support virtual-hosted-style URLs | `Config(s3={"addressing_style": "path"})` | `forcePathStyle: true` | `UsePathStyle: true` |
| Signature version | Presigned URLs must use SigV4 | `Config(signature_version="s3v4")` | Default | Default |
| Checksums | SDK v3.729 and later sign a checksum into presigned upload URLs, and the upload then fails with `BadDigest` | Not needed: presigned URLs carry no checksum | `requestChecksumCalculation: "WHEN_REQUIRED"` and `responseChecksumValidation: "WHEN_REQUIRED"` | Not needed: presigned URLs carry no checksum |

## Credentials

Keep the secret out of your code. The Quickstart programs read the key from the standard AWS environment variables, which every AWS SDK picks up:

```bash
export AWS_ACCESS_KEY_ID=YOUR_ACCESS_KEY
export AWS_SECRET_ACCESS_KEY=YOUR_SECRET_KEY
```

When you create a key, **Download .env** in the console saves a `credentials.env` file with these two lines, so `source credentials.env` sets them. The secret is shown only at creation: if you lose it, rotate the key. See [API Keys](/app/api-keys#rotating-a-key).

## Regions

Fil One has two regions, each with its own endpoint:

| Region | Endpoint |
|--------|----------|
| `eu-west-1` (default) | `https://s3.eu-west-1.filonecontent.com` |
| `us-east-1` | `https://s3.us-east-1.filonecontent.com` |

The endpoint, the region setting and the access key must all refer to the bucket's region. A key belongs to one region and is rejected by the other, so code that works with buckets in both regions needs two clients and two keys.

## Creating buckets

Create buckets in the [console](https://app.filone.com) unless you work only in `us-east-1`. `CreateBucket` over the S3 API is not available in `eu-west-1`. In `us-east-1` it works with a key that has the `CreateBucket` permission, which isn't selected by default. Versioning and Object Lock can only be turned on in the console, when the bucket is created. See [Buckets](/storage/buckets).
