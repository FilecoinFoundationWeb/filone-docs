Buckets are containers for your objects. Every object in Fil One lives inside a bucket.

## Bucket naming rules

Bucket names must be:
- Between 3 and 63 characters
- Lowercase letters, numbers, and hyphens only (**no dots**)
- Must start and end with a letter or number
- Unique within the region
- Not starting with `filone-rag-`, which is reserved

These rules are close to AWS S3's but not identical: in particular Fil One does **not** allow dots (`.`) in bucket names, which AWS S3 permits. If you are migrating a bucket whose name contains a dot, you will need to rename it.

## Creating a bucket

:::note
Whether you can create a bucket through the S3 API depends on the region. `CreateBucket` and `DeleteBucket` are supported in `us-east-1`, but not in `eu-west-1` — in that region buckets must be created in the Fil One console. All other S3 operations (uploading, downloading, listing objects, etc.) work normally via the API in every region.

To use `CreateBucket` or `DeleteBucket` with an access key, grant the key that permission when you create it. See [API Keys](/security/api-keys).
:::

1. From the **Dashboard**, click **New bucket** to open the create form.
2. Enter a bucket name.
3. Choose a **region**: `eu-west-1` Europe (France, the default) or `us-east-1` US East (Michigan).
4. Optionally expand **Advanced settings** to turn on **Versioning**, then **Object Lock**, then **Retention**. Each needs the one before it: until it's on, the next switch shows a **Needs Versioning** or **Needs Object Lock** badge. Retention takes a mode (**Governance**, the default, or **Compliance**) and a duration from 1 day up to 100 years; it starts at 15 days. Leave Versioning off and the bucket keeps only the current copy of each object.
5. Click **Create bucket**. The console opens the new bucket's page, which offers **Create API key**. A key belongs to a single region and must match the bucket's region.

Every bucket is created with encryption enabled automatically.

:::warning Creation-time settings are permanent
Region, versioning, Object Lock, and retention cannot be changed after the bucket exists — there is no update-bucket operation, and a bucket cannot be moved between regions. To change any of them you have to create a new bucket and copy the data across. Enable versioning and Object Lock now if you are likely to want them.
:::

## Listing buckets

<Tabs>
  <TabItem value="aws-cli" label="AWS CLI">
    ```bash
    aws s3 ls --endpoint-url https://s3.eu-west-1.filonecontent.com
    ```
  </TabItem>

  <TabItem value="python-boto3" label="Python (boto3)">
    ```python
    response = s3.list_buckets()
    for bucket in response["Buckets"]:
        print(bucket["Name"], bucket["CreationDate"])
    ```
  </TabItem>
</Tabs>

## Deleting a bucket

A bucket must be empty before it can be deleted, with no objects or object versions left in it.

<Tabs>
  <TabItem value="app" label="App">
    Open **Buckets**, choose **Delete bucket** from the bucket's actions menu, and confirm. If the bucket still holds objects, the console tells you it is not empty. Open the bucket and use **Empty bucket** to remove everything first. See [Buckets in the console](/app/buckets#deleting-a-bucket).

    Deleting from the console works in every region, including `eu-west-1`. Only the Owner and Admin roles can delete buckets.
  </TabItem>

  <TabItem value="aws-cli" label="AWS CLI">
    ```bash
    aws s3 rb s3://my-bucket --endpoint-url https://s3.us-east-1.filonecontent.com --region us-east-1
    ```

    `DeleteBucket` over the S3 API works in `us-east-1`, using a key that has the `DeleteBucket` permission. It is not available in `eu-west-1`, so use the console there.
  </TabItem>
</Tabs>

:::info
Deleted data is no longer accessible. Encrypted residual data can remain in Filecoin storage for a bounded period: see [What happens to deleted data](/storage/objects#what-happens-to-deleted-data).
:::
